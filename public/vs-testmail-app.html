testmail.app alternative: Neverla Mail vs testmail.app

testmail.app is a tidy, inbound-only testing API built around namespaces and tags, with published rate limits, a GraphQL API and a free plan of 100 emails a month. Neverla Mail is a public inbox with a keyless REST API, your own domain and an MCP server, all free. Facts read on testmail.app’s own pricing and documentation pages on 2 September 2026, with the section on where testmail.app is the better fit.

All comparisons

In short

  • Both are inbound-only and both let you invent addresses. testmail.app receives at namespace.tag@inbox.testmail.app, where the tag is anything you type; Neverla Mail receives at anything@ its public domains or yours. Neither sends, neither has webhooks.
  • The free plans are the difference. testmail.app’s Free is 100 emails a month with one day of retention on a random namespace, after a 14-day trial of the paid tiers. Neverla Mail’s free tier has no monthly count, keeps mail 5 days and needs no account.
  • testmail.app’s API is more polished; Neverla Mail’s is more open. GraphQL with wildcard search, spam scores and live long-poll queries versus three REST endpoints — but theirs needs an account and a key, and ours needs neither.
  • Pick testmail.app for a private namespace, long-poll queries, search across a test run and retention up to 30 days. Pick Neverla Mail for a keyless call, a free domain of your own, and an agent that needs an inbox with no account.

What testmail.app does well

testmail.app is what a small team builds when it wants email testing done properly and nothing else. Four things it does that Neverla Mail does not:

  • Live queries. A GraphQL query with livequery: true waits on the server until a matching message exists, for up to a minute, then redirects to itself so the client keeps waiting. That is a polling loop you do not have to write. Neverla Mail’s REST API is polled; only its MCP server waits.
  • Search across a run. Wildcards on subject and body, filters by tag prefix and time, and a SpamAssassin score and report on every message. A test can ask “every message to run42-* since the suite started” in one query. Neverla Mail lists one mailbox at a time.
  • Private, scoped namespaces. Mail in a namespace is readable only with a key authorised for it, and a team can hand each project its own key. Every Neverla Mail mailbox is public.
  • Published rate limits and soft quotas. The documentation gives exact figures — more than 10 requests a second per IP, 5 a second per paid key sustained for an hour — and paid plans allow temporary surges above the monthly allowance. Few services in this category put numbers in writing.

Where Neverla Mail is different

Neverla Mail is built for the case testmail.app’s free plan is too small for and its account model rules out: a job that needs a real inbox with nothing to sign, store or count.

  • No key, no account, no namespace. testmail.app assigns you a namespace and issues a key; every call carries it. Neverla Mail assigns nothing: run-42@mail.neverla.web.id is an inbox the moment mail arrives, and reading it is a GET with the address in the query string.
  • No monthly count. testmail.app Free stops at 100 emails a month; a suite that signs up ten users a run uses that in ten runs. Neverla Mail has no monthly allowance — 1,000 free API requests a day, and no cap on a paid plan.
  • Your own domain, free. At testmail.app a custom domain is on the Unlimited plan, $269 a month billed annually. Here it is one MX record at smtp.mail.neverla.web.id, and every address on the domain is a catch-all inbox — the answer to sign-up forms that refuse a testing domain.
  • An MCP server for agents. testmail.app has none. Neverla Mail’s at https://mail.neverla.web.id/mcp gives an agent an inbox and a blocking wait_for_message of up to 25 seconds, with no key.

For developers: reading a mailbox

The whole difference in one command. This reads a Neverla Mail mailbox with no header, no key and no account:

shell
$ curl -sG https://mail.neverla.web.id/api/v1/mailbox --data-urlencode "address=anything@mail.neverla.web.id" | jq '{count, alias}'

The testmail.app equivalent is a GraphQL query for inbox(namespace, tag) with a bearer key, or the JSON API with apikey, and with livequery it waits for you. It is the nicer API to write a test against — and it needs the account behind it. On Neverla Mail the wait is a loop with a deadline; the Playwright and Cypress guides have it, and the OTP guide covers pulling the code out.

The addressing habit carries over almost unchanged: testmail.app’s namespace.tag@inbox.testmail.app becomes tag@mail.neverla.web.id here, or tag@your-domain.com once the MX record is set. A suite that builds tags from a run id keeps doing so.

For AI agents

testmail.app publishes no MCP server and no llms.txt; an agent can call its API with the team’s key like any script. Neverla Mail’s server at https://mail.neverla.web.id/mcp gives an agent an inbox with no key: create_inbox, a blocking wait_for_message of up to 25 seconds, read_message.

For an agent that must sign itself up to something, the keyless server is the difference between finishing and stopping at a form. Email for AI agents covers the loop and the guard rails.

Switching from testmail.app

Both are inbound-only, so the switch is the address and the query:

  1. Change the address builder. {namespace}.{tag}@inbox.testmail.app becomes {tag}@mail.neverla.web.id, or a domain of your own with its MX at smtp.mail.neverla.web.id.
  2. Replace the live query with a wait loop. A GET on /api/v1/mailbox every second until count is above zero or the deadline passes. The guides have it in TypeScript and Python.
  3. Remove the key. Delete the API key from CI and the GraphQL client from the lockfile. Nothing replaces them.
  4. Check what you relied on. Search across tags, spam scores and 30-day retention have no equivalent here: one mailbox per call, 5 days, no scoring. Attachments still work, up to 5 MB.

Which one, for what

The honest split:

Pick Neverla Mail when

  • the call must be keyless, or the monthly count on the free plan is the problem;
  • you want a catch-all inbox on your own domain without the top-tier price;
  • an AI agent needs an inbox with no account behind it.

Pick testmail.app when

  • you want live queries and search across a whole test run;
  • the mail must be private to a namespace, with a key per project;
  • you need retention up to 30 days, or an SLA on the Enterprise plan.

When to stay with testmail.app

Three situations where switching would cost you something real:

  • Your tests carry real data. A namespace is private to its keys; every Neverla Mail mailbox is public, on the public domains and on yours. A test that mails a customer’s details needs the first.
  • Your suite searches. If tests ask for “all messages to run42-* with subject Welcome*”, that is one query there and a loop over addresses here. Keep the query.
  • You are on Essential and it is enough. $9 a month for 10,000 emails and a real API is not a cost worth engineering around. Switch when the key in CI, the monthly count or the domain price is the thing that hurts.

Questions

Is Neverla Mail a free alternative to testmail.app?

For receiving and reading test mail, yes, with no account, no key and no monthly count. It does not replace testmail.app’s live queries, search, spam scoring, private namespaces or long retention, which do not exist here.

What does testmail.app’s free plan include?

100 emails a month, one day of retention, one randomly assigned namespace and unlimited addresses and users, after a 14-day trial of the paid plans. Its pricing page lists full API access from Essential at $9 a month billed annually.

Can I use my own domain with testmail.app?

Custom domains are listed only on the Unlimited plan at $269 a month billed annually. On Neverla Mail any domain you own becomes a catch-all inbox with one MX record, free. The catch-all guide shows the setup.

Which one has published rate limits?

Both. testmail.app documents a global limit above 10 requests a second per IP and per-key limits (5 a second sustained on paid keys; 1,000 an hour, 10,000 a day and 100,000 a month on free keys). Neverla Mail documents one read a second per address, 60 requests a minute and 1,000 a day per IP without a key, and no per-minute or daily cap on a paid key. Neverla Mail’s limits page has the rest.

Which one works with AI agents?

Neverla Mail runs a free keyless MCP server with a blocking wait_for_message; testmail.app publishes none, though its API can be called by an agent holding the team’s key. The client guide has the Neverla Mail configuration.
